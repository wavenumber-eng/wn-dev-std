# 2026-10-08

Release version: `2026.10.8`

The Rust profiles accept `cargo fmt --package ROOT_NAME -- --check` (or `-p`)
when the audited root has an explicit, isolated single-package workspace and
the exact owned name is selected. Sibling path dependencies retain their own
formatting authority. Multi-crate, virtual and ambiguous workspaces retain the
canonical `cargo fmt --all -- --check` lane.

The ownership proof refuses additional Cargo manifests, internal dependency or
patch/replace paths, alternate selectors/manifests, source-directory links,
nonregular root manifests and exceeded read/inventory/traversal limits. Real
argv validation replaces misleading formatting-marker matches. Other Cargo
requirements, runner normalization and strict hygiene limits stay unchanged.

The existing Lit template lock now uses source-map-js 1.2.2, the patch for
[GHSA-68fv-2mgg-jv7q](https://github.com/advisories/GHSA-68fv-2mgg-jv7q).
There is no frontend feature or asset change.

Qualification includes formatter ownership/refusal fixtures, existing Rust
profiles/hygiene, full Rack signoff, both executable template gates, package
build/Twine checks, installed-wheel smoke and public CI. PCB Engine consumes
this released standard through its own pinned governance/signoff path.
