# 2026-10-22

Release version: `2026.10.22`

This release addresses the [eMudhra / emSign CA incident](https://discuss.python.org/t/information-for-python-users-regarding-emudhra-emsign-ca-certificate-security-incident/109576).
The optional PyPI freshness check uses Certifi >=2026.10.19 explicitly, with
hostname and certificate verification enabled. It excludes host roots and
SSL_CERT_FILE / SSL_CERT_DIR overrides. Corporate proxies requiring private
CAs must arrange direct access for this optional check; connection failures
remain warnings and never retry with weaker TLS settings.

The reviewed standard and bundled template markers advance to `2026.10.22`.
CI uses uv 0.13.4 and Node 24.22.1, refreshes Linux system certificates, and
builds isolated distributions using `python -m build --installer uv`. This
avoids an independently seeded, outdated pip CA bundle. Any pip used outside
this workflow must be >=26.2.2. Rebuild deployed containers without cached CA
layers and update host stores separately; installing this package does not
modify the operating system trust store or already copied templates.

Both copy-owned templates require patched Node 22.23.4+, 24.22.1+, or 26.12.1+
on those release lines, enforce that floor at installation, and retain npm
11.16.0 and existing dependency versions. Existing template consumers must
copy these prerequisite and guard changes into their owned projects.

Qualification covers real TLS trust contents, verification failure behavior,
Node floor rejection, both clean template signoffs, full Rack signoff,
package build/Twine checks, and installed-wheel template copying and audit.

The existing Lit dependency audit reports two moderate findings through
Vitest 5.0.2 and one high finding through Vite 8.3.1. Dependency resolutions
are unchanged by this CA patch. The audit remains enabled and blocks complete
signoff; these separate dev-tool advisories need review before a release can
claim a fully passing signoff.
